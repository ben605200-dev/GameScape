## [Unreleased]

### Added

- Phase 1 foundations: monorepo workspace (pnpm + Turborepo), root hygiene files.
- Privacy gate: `scripts/privacy-scan.mjs` and CI workflow.
- Community standards gate: `scripts/community-standards-check.mjs` and CI workflow.
- Community files: README, LICENSE (Apache-2.0), NOTICE, CONTRIBUTING, CODE_OF_CONDUCT (Contributor Covenant 2.1), SECURITY, SUPPORT, issue and PR templates.
- Desktop app scaffold: Tauri v2 + React 19 + Vite 8 (`apps/desktop`), branded for GameScape and integrated into the monorepo. Rust side compiles clean (`cargo check`); frontend builds clean.
- Phase 0 spike S1/S2-lite **passed** — WebView2 surfaces re-parented into the Windows desktop layer (behind desktop icons): classic topology, two monitors with a negative-coordinate arrangement, live rendering visually verified, clean teardown. See `docs/engineering/spike-s1-results.md`.
- Design tokens package (`@gamescape/ui`) — dark/light themes, typography, spacing, radius and motion tokens consumed by the app.
- Desktop app shell: sidebar navigation (9 sections), top bar with theme switcher, Home dashboard with live status cards; theme preference persisted through the settings store.
- Local storage foundation: JSON settings store and a SQLite database with versioned migrations under `%APPDATA%\GameScape`.
- Bundled seed catalogue (fictional preview data) with Rust-side validation, powering the Home shelf and the Wallpapers grid.
- ADR-0002: shell styling approach (tokens-first; Tailwind adopted with the Phase 3 screens).
- Interactive wallpaper prototype **validated on the desktop**: a cursor-reactive light field renders behind desktop icons, driven by a global-cursor bridge in the core (no input capture, no focus stealing). Evidence and limitations in `docs/engineering/spike-s1-results.md`.
- Wallpaper detail pages: clickable cards, full metadata, and a live pointer-reactive preview for interactive entries. The `interactive` flag now lives in the catalogue schema, the Rust model, and the seed.
- Fixed: the spike launch gate now recognises the interactive prototype mode.
- Personal Library **import pipeline** (Phase 3 start): file-picker and drag-and-drop imports for JPG/PNG/WEBP/GIF with magic-byte validation, SHA-256 duplicate detection, decode probing, managed copies in the library folder, JPEG thumbnails, and per-file result reporting (imported / duplicate / unsupported / invalid / corrupted / failed).
- Library page: real grid with thumbnails served through the Tauri asset protocol, per-item removal, and live import progress rows.
- Dev automation hooks (`GAMESCAPE_DEV_IMPORT`, `GAMESCAPE_DEV_FAVOURITE`, `GAMESCAPE_START_HASH`) for local test harnesses — never active in normal use.
- Catalogue **search, filters and sorting**: instant search across titles/games/tags; filters for game, media type, orientation and resolution (both derived from dimensions); newest/A-Z sorting; live result count and clear-all.
- **Favourites**: star toggle on cards and detail pages, persisted in SQLite, with a working Favourites page.
- Seed catalogue expanded from 5 to 14 fictional entries across 4 games and all three media types — including portrait and ultrawide layouts so filters have real variety.
- Shared `WallpaperCard` component now used by Wallpapers, Favourites and the Home shelf.
- Interactive previews are now **per-wallpaper**: an `effect` descriptor (`orbit` / `ribbon` / `grid`) rides in the catalogue schema (validated in the Rust model) and each effect renders tinted with the wallpaper's own placeholder palette. Fixes a gap where every interactive preview rendered the same hardcoded effect.
- **Fixed: the content area could not scroll** — tall pages (e.g. the wallpapers grid) were clipped with no scrollbar. Root cause: a flex/grid `min-height: auto` trap where the main column grew to content height instead of staying viewport-bound. The layout chain now sets `min-height: 0`; the sidebar also scrolls in short windows. Verified in-window with a scrolled capture.
- Dev hook `GAMESCAPE_DEV_SCRIPT` for window-state verification harnesses — never active in normal use.
- **All wallpapers are now interactive**: every catalogue entry carries an effect descriptor (seed mix: orbit ×5, ribbon ×5, grid ×4), the detail view renders the live cursor-reactive preview for **every** wallpaper (explicit opt-out via `interactive: false` remains), cards show each wallpaper's effect style instead of a generic badge, and entries without explicit effect data fall back to a deterministic style.
- **Metadata editing**: library item detail page — rename imports, edit descriptions and tags (validated server-side), with file info (dimensions, size, SHA-256, path), *Show in Explorer*, and a safe remove with an optional permanent file deletion.
- **Collections**: create collections, filter the library by collection, and tick memberships from any item — counts update live; deleting a collection keeps the wallpapers.
- **Integrity tools**: *Check integrity* scans every managed file (missing / changed detection) with per-item actions — *Locate file…* (relink: re-validated, re-copied and re-thumbnailed like an import) and *Remove entry*.
- **Library location setting**: view, change or reset the managed library folder (new imports go there; existing files stay put).
- Fixed: settings saves now **merge** instead of replacing — toggling the theme can no longer wipe the library directory setting.
- **Phase 4 media pipeline**: MP4 imports with container probing (duration, dimensions, audio-track detection via a pure-Rust MP4 parser); GIF analysis (frame count + loop duration); schema v2 (`frame_count`, `has_audio` columns); real **video playback** (controls, loop, muted autoplay) and **animated GIF playback** on library item pages; **automatic poster-frame generation** for videos (first playable frame captured in the WebView, validated and stored by the core); reduced-motion respect; and the **first Rust unit tests** (GIF analysis, MP4 detection, duration formatting).
- Fixed: video poster frames now capture correctly — cross-origin asset-protocol media **tainted the capture canvas** and blocked `toDataURL`. Posters now load through a same-origin, size-capped data pipeline from the core (`library_read_data`), and the library grid refreshes the moment a poster lands.
- **Phase 5 desktop host (first slice)**: real wallpaper application — static images via the documented `IDesktopWallpaper` COM API (per-monitor, Fill position, WebP→PNG conversion, previous-wallpaper restore stored in schema v3); animated GIF/MP4 wallpapers render in **per-monitor host windows on the desktop layer** (classic + raised topologies) with self-healing re-attach after explorer restarts and clean teardown on exit; **"Set as desktop wallpaper"** on every library item; live Desktop-layer card on Home with Pause/Resume, Stop and Restore-previous-wallpaper controls.
- **Wallpaper fit is now automatic**: applied static wallpapers always fill the screen edge to edge, whatever their original size — configurable under Settings (fill / fit / stretch / center / span); the fit in place beforehand is remembered per monitor (schema v4) and *Restore previous wallpaper* puts it back untouched; animated surfaces follow the same fit.
- **Performance governor**: a 2-second watch pauses wallpaper animation whenever a fullscreen app (games, fullscreen video) takes the foreground or the PC switches to battery, resumes automatically, shows the reason on the Home card, and layers cleanly under the manual Pause/Resume — surfaces created while paused start paused.
- **Installer**: the desktop app now builds a per-user NSIS setup executable via `tauri build`; the app is version 0.5.0.
- **No more edge lines**: wallpaper surfaces over-scan 12px past the window chrome at every monitor edge (with a black window background), and the media is hard-sized to cover the window — no border or gutter pixel can show as a line at the screen sides. Verified by pixel-sampling: the outermost visible screen columns are pure wallpaper content on both monitors.
- Fixed: **wallpaper surface pages had no Tauri IPC access** — the default capability was scoped to the `main` window only, so `convertFileSrc` threw inside surface pages and animated wallpapers could render blank. The capability now covers `gs-wallpaper-*`; the surface page also reports its state and any error through its window title (mirrored by the host) so failures are diagnosable instead of silent.
- **Turn wallpapers off**: a *Turn off* button on the Home desktop card and a toggle on every library item (*Set as desktop wallpaper* ⇄ *Turn off desktop wallpaper*) stop animation, put the previous wallpaper back, and remember the off choice — nothing re-applies behind your back.
- **Startup restore**: the wallpaper last applied comes back automatically when the app opens (skipped when wallpapers were turned off or the file is gone; local test harnesses are exempt).
- **Wallpaper rotation**: change your wallpaper on a schedule — Settings → Wallpaper rotation (off by default; every 5/15/30/60 minutes). It cycles through the wallpapers in your library, skips missing files, respects *Turn off* (nothing re-applies afterwards) and the governor (animation starts paused while a fullscreen app is up); the Home card shows the interval.
- **System tray**: GameScape now lives in the system tray — closing the window keeps it running (wallpaper, rotation and the governor stay active); left-click the tray icon to show/hide the window; the tray menu offers *Open GameScape*, *Turn off desktop wallpaper* and *Quit*.
- Fixed: **MP4 files could not be picked for import** — the file dialog (and the integrity tool's relink dialog) only listed image extensions; both now include MP4 alongside jpg/jpeg/png/webp/gif.
- **Per-monitor wallpapers** (completes Phase 5's desktop host): assign different wallpapers per screen — the item page gains an *Apply to* selector (all monitors, or any single monitor with its resolution); animated surfaces swap per monitor without disturbing the others, static applies touch only the chosen screen, startup restore remembers the target monitor, and the Home card notes when monitors are running different wallpapers.
- **Phase 6 begins — desktop widgets (first slice)**: a widget layer on the same self-healing desktop foundation as the wallpapers — placeable cards that live above the wallpaper and behind the icons. The Widgets page adds, enables/disables, positions (per-monitor pixel coordinates), resizes and removes widgets. Three starter widgets: **Clock**, **System monitor** (live CPU / RAM / uptime sampled in Rust) and **Wallpaper status** (what is currently applied, with a thumbnail). Widgets re-attach after explorer restarts and are restored on launch.
- **Widget slice 2**: **Calendar** (month grid with today highlighted) and **Countdown** (custom label + target date, live countdown) join the widget kinds; countdown settings are edited in the Widgets page and validated as JSON in the core; corner-preset buttons (↖ ↗ ↙ ↘) snap a widget to any corner of its monitor; changing settings rebuilds only that widget.
- **Widget slice 3 — draggable, edge-clean, and a Text widget**: widgets can be **dragged around the desktop with the mouse** (a lightweight watcher grabs only clicks that truly land on the desktop — never clicks meant for app windows — moves the card live, keeps it within its monitor and remembers the drop position); every layer window is now **region-clipped to its client area**, so the pale window-chrome lines at the edges are gone for widgets and wallpaper surfaces alike; and a new **Text** widget shows custom text with selectable font (Segoe UI, Georgia, Consolas, Impact, Comic Sans MS) and size (10–200 px), edited in the Widgets page.
- **Catalogue wallpapers are now real and applicable**: every default catalogue entry can be set as your wallpaper — GameScape renders the entry's art direction (its palette gradient plus the orbit / ribbon / grid motif, deterministic per entry) into a 1920×1080 PNG in Rust, keeps it in your library (`public_catalogue` source) and applies it, all from one button on the wallpaper's page. Generated entries appear in your library and can be re-applied from their item page; repeats reuse the existing file instead of re-rendering.
- **Interactive wallpapers now live on the desktop**: catalogue entries with a cursor-reactive effect apply as a **live effect** — the wallpaper follows your mouse across the screen (orbit / ribbon / grid, tinted with the entry's palette), driven by the same cursor bridge the Phase 0 spike proved (cursor polling, no input capture, no focus stealing). The governor pauses the effect along with everything else, it survives explorer restarts and is restored on launch, and the entry is still saved to your library as a static image when applied.
- Interactive wallpapers **track the cursor tightly**: the bridge polls at display rate while an interactive surface is live (12 ms instead of 40 ms), the effect's catch-up constant dropped from ~200 ms to ~60 ms, and the trail is shorter — the glow now arrives in ~100 ms instead of half a second.
- **Widget slice 4 — click-through interactivity + Launcher**: short clicks on a widget now reach its content (forwarded into the webview with hover, press and release), while press-and-move still drags the widget — distance and time tell the two apart. First to use it: the **Launcher** widget — up to 6 clickable shortcuts (https links or file/app paths) living on your desktop, clicked right where they sit.
- **Widget slice 5 — boxless clock and text + more fonts**: the Clock and Text widgets now float directly on the desktop with **no card behind them** (a colour-key layer makes the page background fully transparent — only the content shows); the Clock gained font choices, and the font list grew to **14 fonts** for both (Segoe UI / UI Variable, Georgia, Trebuchet MS, Verdana, Tahoma, Consolas, Cascadia Code, Courier New, Impact, Arial Black, Segoe Script, Ink Free, Comic Sans MS), with the Text widget keeping its size control (10–200 px).
- Fixed: **library thumbnails for large videos and generated wallpapers** — poster capture now loads through the asset protocol with CORS (`crossOrigin = "anonymous"`), so the canvas stays untainted for any file size (a 66 MB clip exceeded the old 60 MB data-pipeline cap and silently never got a poster), and images without thumbnails (like freshly generated catalogue wallpapers) are downscaled into thumbnails automatically.
